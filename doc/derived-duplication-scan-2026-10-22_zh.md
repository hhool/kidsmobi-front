# 派生重复扫描：把「只看 8 组」这个盲点补上

日期：2026-10-22
起因：B 轨收尾时用户指出——我只给 what-buyers-say 那一对做过「正文是否真重复」的测量，另外 7 组没做。补齐测量时顺手问了一句：**只盯着 8 组硬编码对，新写的内容谁来管？**
结论：**没人管。**把扫描改成从构建产物派生之后，立刻抓到两对真问题，其中一对顺带暴露了两篇已发布文章的数字与目录不符。

---

## 一、方法：先修测量，再谈结论

上一版 `check:pairdrift` 有两个盲点，任何一个都会让结论失真：

### 1. `df >= 20` 抓不到「只出现在 4-9 页」的模板段落

文档频率判定样板，前提是样板出现在很多页上。但站点里有一类模板输出只属于某个栏目：

| 模板小标题 | 出现页数 |
| --- | --- |
| `Method and limits`（news） | 4 |
| `What this data cannot tell you` / `What this guide cannot tell you`（资产页） | 4 |
| `How these numbers were produced` / `How these counts were produced`（资产页） | 3 |

它们只出现在 3-4 页，永远够不到 20，于是被当成正文。**后果是实测出来的**：两篇电动骑乘车文章的正文重叠算出来 **0.102**，逐条核对共享 8-gram 后发现一半以上是这段「方法与边界」的逐字重复——真实正文重叠只有 **0.046**。

修法：小标题按词袋（≥0.6，单链接）聚类，一个簇覆盖 ≥3 页即判为模板段落，**正文与小标题比对都剔除**。这样 `How these counts were produced` 和 `How these numbers were produced` 不用有人手工列举就会被认成同一段。署名行（`…Editorial Team · Published <日期>`）带日期，任何 df 阈值都认不出它是模板，用正则单独剔除。

### 2. 配对表是硬编码的 8 组

新增文章不在表里，就永远不会被比较。改成从 dist 派生：**所有编辑类叶子页两两比较**（文章、资产页、transparency 页）。排除两类：

- 商品详情页——规格表本来就是同一组字段填不同值；
- 列表型页（hub / 栏目页 / 类型页）——hub 复述自己的子条目是它的职责。

阈值 `bodyOnly > 0.08`、`subheadSim > 0.6`。今天最差的一对是 0.053 / 0.2。

## 二、发现 1：两篇电动骑乘车文章在做同一件事

扫描排名第一：`electric-dirt-bikes-for-kids` ↔ `kids-electric-bike-development-trends-2026`，正文 **0.046**、小标题 **0.6**（`Five checks that transfer` ↔ `Three checks that transfer`）。

读原文时发现更糟的事：**两篇的数字都不对，而且互相矛盾。**

| 项目 | 两篇原文 | 目录实测 |
| --- | --- | --- |
| 标题标电压 | 14/16（12V×8、24V×4、36V×1、6V×1），没标的两个是扭扭车和头盔 | **15/16**（12V×8、**24V×5**、36V×1、6V×1）；没标的只有一个，是扭扭车 |
| 家长遥控 | 10/16 标题 | **11/16** 标题（12V 6/8、24V 5/5） |
| 充电时间 | 写在 6 个规格表里 | **0/16**——没有一个车型标充电时间 |
| 承重 | 13/16 | **14/16**（55-264 磅） |
| 最低年龄 | 15/16，其中 13 个 ≥36 个月 | **16/16**，其中 **14 个** ≥36 个月（13 个 36 个月 + 1 个 37 个月） |
| 需组装 | 15/16 | **16/16** |
| 12V 时速 | 「12V 车型在标题里写 1.5-4 MPH」 | 12V 两辆分别写 **1.5** 和 **3.5** MPH；**4 MPH 那辆是没标电压的扭扭车** |

最后一行是最典型的一个：`1.5-4` 来自 Gotrax RT1 标题里的 `for Toddlers 1.5-4`，那是**年龄区间**，不是时速。

两篇还各自把「16 个车型」和「其中的头盔」混着数：目录里挂电动骑乘标签的是 **17** 个，其中 1 个是品类页不展示的头盔，所以计数口径是 **16**。

**处置**：

1. 全部数字按实测改正（中英文同步），`scripts/fix-electric-news-figures.mjs`，dry-run + `?cb` 回读验证。
2. 数字改成**可复算**：新增 `scripts/count-electric-rideon-figures.mjs`，从线上目录重打这张表。下次再引用这些数字，先跑它。
3. 意图分流：越野那篇的小标题改成 `Five checks before it goes off-road`，五项核对全部改成「上非铺装路面才成立」的说法，年龄/容量那两条指向电压篇的逐档数字并加交叉链接。

结果：小标题 **0.6 → 0.2**；正文 0.046 → 0.053（两篇现在都要引同一组实测数字，这点重叠是数据集本身带来的，仍远低于 0.08）。

## 三、发现 2：两篇「研究」页小标题字面相同

`guides/beginner/balance-bike-vs-training-wheels` ↔ `news/science/balance-bike-research`，`subheadSim = 1.0`——两页都有一节叫 **`What the studies measured`**，讲的都是同一家葡萄牙团队那两项研究、同一组数字（4.16 / 5.97 / 7.27 岁，100% vs 约 77%）。

正文 8-gram 重叠低只是因为措辞不同，实质是同一份研究写了两遍——正是 what-buyers-say 那个失效模式。

**处置**：购买指南保留「这个决定能依据的结论」，压成一段，研究设计、样本量、同行评审的质疑交给研究页，并链过去（`scripts/separate-research-duplication.mjs`）。数字一个没删，只是长版只留一处。

## 四、教训

1. **数字必须可复算，不能只可信。**这些数字当初是手写时数过一遍的，没有第二次校验。两篇互相矛盾、且都与目录不符，却一直挂着「每个数字都数自已发布目录」这句话。现在这句话有脚本兜着。
2. **硬编码的对会漏掉之后写的全部内容。**派生成对的代价是多算 71 页的两两组合（几秒），换来的是新文章一写就进监控。
3. **反向验证必须先确认破坏真的落在守卫看得见的地方。**这次连续三次「守卫没红」都是我的 payload 放错了位置——放进 `<header>`、放进尾部模板段落、payload 太短。放进真正文（第一个 `<h2>` 之前）才测出 `bodyOnly 0.23 > 0.08`。
4. **守卫假绿还有一个新花样**：第一版派生扫描用 `...subheadMatch()` 展开，`subheadSim` 字段名对不上，值是 `undefined`，`undefined > 0.6` 永远为假——扫描看着全绿，其实小标题判定从来没生效。修好字段名后，研究页那一对立刻报出 1.0。**展开对象时字段名错了不会报错，只会静默失效。**

## 五、验证

- 14 项静态守卫全绿；`tsc --noEmit` 0 错；水合探针 38/38。
- `check:pairdrift`：8 组命名对 + 13 组派生对全部通过；派生扫描前两名 0.053 / 0.043（阈值 0.08）。
- 反向验证：把研究页真正文 3000 字符粘进越野篇 → 精确报 `bodyOnly 0.23`；还原即绿。
- sitemap 仍 270 URL，legacy-redirects 45 精确 + 10 前缀不变。
